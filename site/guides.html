First run and permissions

About 5 minutesSettings›Setup checklist

Until everything's in place, Settings opens with a setup checklist ("Finish setup to start dictating"), and the widget shows "Finish setup". Each item has its own fix button.

  1. Install. Open the DMG and drag Mouthpiece into Applications. It isn't notarized by Apple yet, so open it once, then go to System Settings›Privacy & Security and click Open Anyway. Or skip that step with the one-line install:
    Terminal
    curl -fsSL https://jfinchy.github.io/mouthpiece/install.sh | sh
  2. Download a speech model. The checklist's Choose a model button takes you to Voice›Whisper model. Base (57 MB) is a good start; see choosing a model.
  3. Grant the permissions you need. Only the first two are needed to dictate.

Microphone Required

macOS asks on the first recording, or click Allow microphone in the checklist. If it was turned off, Open System Settings goes straight to Privacy & Security › Microphone.

Accessibility To paste

Lets Mouthpiece press ⌘V for you. Without it, your words are copied (and saved to History) instead, and the widget offers "Allow pasting". Not needed if you turn on Copy only — don't auto-paste into the active app under Integrations › Delivery.

Input Monitoring Optional

Only for double-tap Fn. Turn on Double-tap Fn to start/stop recording under Dictation › Push-to-talk key, then allow Mouthpiece in Privacy & Security › Input Monitoring.

System audio Meetings

On macOS 14.4 and later, macOS asks to let Mouthpiece record system audio the first time a meeting captures it. That's what lets calls on headphones be transcribed. Speaker names from the call window also need Accessibility.

After an update, pasting stopped? If Accessibility already shows Mouthpiece as on but pasting doesn't work, switch it off and on again in System Settings. The checklist's tooltip says the same.

Choose a speech model

Settings›Voice›Whisper model

All three are English whisper.cpp models running on your Mac's GPU. Each row shows Speed and Accuracy bars; click Download, and the active one is marked Active. Downloads are checked against known checksums.

ModelSizePick it when
Tiny (English)32 MBSpeed matters most, or an older M1 is busy
Base (English)57 MBThe default. Balanced for everyday dictation
Small (English)190 MBYou want fewer misheard words and can wait a little
  1. Download the model you want and select it. Every model a mode uses is warmed at launch, so the first dictation isn't slow.
  2. Leave Transcribe while you talk on (it's the default). Each phrase is transcribed at the pause after it, so only the last few seconds are left when you stop.
  3. Optional: a mode can use a different model than the rest. In Modes, change a mode's model from Global model to the one you want.

Local LLM cleanup

OptionalSettings›LLM

Without an LLM you still get app formatting, casing, file tags, lists and snippets. Cleanup adds a pass for rambling or casual speech, on this Mac.

  1. Get a local model server. Install Ollama, or start the local server in LM Studio (port 1234), llama.cpp's llama-server (8080) or Jan (1337). Mouthpiece finds them on their own.
  2. Pick a model under LLM refinement. ✓ means it's ready; ⬇ means selecting it downloads it once (size shown). Models from other servers are tagged with their source, and each shows its last round-trip time. Small models are the quick ones; "thinking" models can take far too long.
  3. Keep it fast. Leave Only refine when it's needed (faster) on: clean transcripts paste right away, and the LLM runs only for filler words, repeats or long unpunctuated stretches (always in Casual mode or modes with custom instructions).
  4. Already have a .gguf file? Under Model files on this Mac, files from LM Studio's, Jan's and the Hugging Face folders and ~/models have an Add to Ollama button. For anything else, use Choose a .gguf file…. Ollama has to be running; nothing is downloaded.
Ollama's cloud models are hidden and never used, so cleanup can't leave your Mac. If one was already saved, Settings says so and asks you to pick a local model.

Modes and app rules

Settings›Modes

A mode decides how dictation is formatted for the app that was in front when you started recording. It ships with CLI for terminals (Terminal, iTerm, kitty, WezTerm, Warp), Messaging for Slack, Messages and Discord, and Default for everything else. Edit those or add your own.

  1. Click + Add mode and give it a name.
  2. Pick its base behavior: Plain (sentences), Casual (relaxed, always refined) or CLI (shell-shaped output and file tags).
  3. Use + Add app to assign apps. Running apps are listed first, with common ones under Other apps so the app doesn't have to be open. After you dictate somewhere new, a shortcut appears: "Add App to: Choose a mode…".
  4. Choose the speech model (Global model or a specific one) and the LLM: No LLM refinement, Refine with global LLM, or a specific local model.
  5. Optional: add extra instructions for the LLM, e.g. "Always sign off with 'thanks, Jake'."
History can re-run a past dictation through a different mode: click Reprocess on an entry, preview, then copy the result or replace the entry.

Vocabulary and snippets

Settings›Vocabulary

  1. Add your terms. Type into Add a term (e.g. kubectl) and press Return. Or adopt a bundle from Vocabulary books and prune it afterwards. Your terms bias Whisper and are passed to the LLM.
  2. Use names from your project. Leave Use names from your project on. The page shows the project it detected; it's picked up the next time you dictate in a terminal or editor inside a repo. It stays in memory on this Mac.
  3. Learn from corrections. With Learn from my corrections on, fixing the same word twice in History (the pencil icon) shows a card here, like "You've corrected 'post gress' to 'Postgres' 2 times. Add it?". Adding it saves the term and a replacement rule, listed under the vocabulary and removable.
  4. Snippets. Under Snippets, add a Trigger phrase (e.g. standup update) and the Text to paste. Say the trigger by itself to paste the text.

Reply to a waiting Claude Code agent

About 2 minutesSettings›Coding agents

When an agent finishes or asks for permission, the widget shows "Claude is waiting · folder". Press the reply shortcut, answer out loud, and the text is pasted into that agent's window, then you're back where you were.

  1. Open Coding agents›Claude Code hook and click Copy hook config. The snippet points at a small script Mouthpiece keeps in its app data folder, which carries this install's secret token.
  2. Merge it into the hooks in ~/.claude/settings.json, alongside any hooks you already have. Its shape (copy yours from Settings, it has your home folder in the path):
    ~/.claude/settings.json
    {
  "hooks": {
    "Notification": [{ "hooks": [{ "type": "command", "command": "'/Users/you/Library/Application Support/dev.mouthpiece/bin/mouthpiece-hook'" }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "'/Users/you/Library/Application Support/dev.mouthpiece/bin/mouthpiece-hook'" }] }],
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "'/Users/you/Library/Application Support/dev.mouthpiece/bin/mouthpiece-hook'" }] }]
  }
}
    Notification and Stop tell Mouthpiece an agent is waiting; UserPromptSubmit clears it when you answer in the terminal yourself.
  3. Check the Reply shortcut (⌃⌥R by default; click it to record a new one). Optionally turn on Play a soft sound when an agent starts waiting.
  4. To submit replies by voice, turn on Say "press enter" to submit — presses Enter after pasting under Integrations›Delivery. Then end a reply with "send it" or "press enter".
  5. Start a Claude Code session and let it finish a task. The pill appears and the agent shows under Waiting now. Press ⌃⌥R, speak, press it again.
Which terminals work best. Mouthpiece finds the agent's window by its folder name in the window title. Terminal, VS Code and Cursor usually show it; iTerm, Orca and Warp often don't. If it can't be sure, the reply is copied to the clipboard instead, and it never pastes into a different app. Enter is only pressed when the window title names the agent's terminal; otherwise the text is pasted for you to check and press Return.

Deep links for Raycast, Alfred and the shell

mouthpiece://start-recording, stop-recording, toggle-recording

Any web page can open a mouthpiece:// link, so each link must carry this install's token, read from ~/Library/Application Support/dev.mouthpiece/agent-hook-token. Links without it are ignored and logged. Start and stop are idempotent, so scripts don't need to track whether it's recording.

From a terminal

Terminal
open "mouthpiece://toggle-recording?token=$(cat ~/Library/Application\ Support/dev.mouthpiece/agent-hook-token)"

A shell function

Add to ~/.zshrc, then run mp, mp start or mp stop.

~/.zshrc
mp() {
  local token
  token=$(cat ~/Library/Application\ Support/dev.mouthpiece/agent-hook-token)
  open "mouthpiece://${1:-toggle}-recording?token=$token"
}

Raycast script command

Save as mouthpiece-toggle.sh in a folder Raycast loads script commands from, and make it executable with chmod +x. Give it a hotkey in Raycast.

mouthpiece-toggle.sh
#!/bin/bash
# @raycast.schemaVersion 1
# @raycast.title Toggle dictation
# @raycast.mode silent
# @raycast.packageName Mouthpiece

token=$(cat "$HOME/Library/Application Support/dev.mouthpiece/agent-hook-token")
open "mouthpiece://toggle-recording?token=$token"

Alfred

In a workflow, connect a Hotkey trigger to a Run Script action (language /bin/bash) containing the last two lines of the Raycast script.

Hammerspoon

~/.hammerspoon/init.lua
local f = io.open(os.getenv("HOME") .. "/Library/Application Support/dev.mouthpiece/agent-hook-token")
local token = f:read("*l"); f:close()

hs.hotkey.bind({ "ctrl", "alt" }, "M", function()
  hs.urlevent.openURL("mouthpiece://toggle-recording?token=" .. token)
end)
Keep the token out of shared dotfiles: read it from the file at run time, as these do, rather than pasting the value.

Send every dictation to a webhook

Settings›Integrations›Output webhook

Off by default: dictated text only leaves the Mac once you set a URL. Each delivered dictation is sent as a JSON POST in the background, so a slow endpoint never delays the paste; failures go to the log.

  1. Paste your URL into the field (n8n, Zapier, Make.com, or a Slack or Notion incoming webhook).
  2. Click Send test event. You should see Test event delivered.
  3. Handle this body:
    POST body · application/json
    {
  "timestamp_ms": 1762425600000,
  "text": "git commit -m \"update readme\"",
  "summary": null,
  "app_name": "Terminal",
  "mode": "cli"
}
    summary is the work-journal line when that's on; it's often null because the summary is written after the webhook fires.

Try it locally first

This prints each payload in your terminal, without sending your text anywhere. Use http://127.0.0.1:8787 as the webhook URL.

Terminal
python3 -c '
from http.server import BaseHTTPRequestHandler, HTTPServer
class H(BaseHTTPRequestHandler):
    def do_POST(self):
        print(self.rfile.read(int(self.headers["Content-Length"])).decode(), flush=True)
        self.send_response(200); self.end_headers()
HTTPServer(("127.0.0.1", 8787), H).serve_forever()'

Record and transcribe a meeting

Settings›MeetingsPhase 2 in testing

  1. Enroll your voice once, so your turns are labelled "You": Voice›Voice Isolation › Enroll voice, then speak naturally for a few seconds and press Stop.
  2. Set People in the meeting if you know it. Setting the number gives the best split, especially when voices sound alike; leave it on Work it out otherwise.
  3. Click Start meeting, or choose Start Meeting from the menu bar icon. The widget shows a red dot, level meter and timer. Let people know you're recording.
  4. Or let it ask: with Offer to record when a call starts on, joining a Zoom, Google Meet, Teams, Slack Huddle, Webex, FaceTime or Discord call shows "Record App?" in the widget, and "Call ended · Stop?" afterwards.
  5. You can keep dictating with push-to-talk while it records; those words are kept out of the meeting.
  6. Click Stop meeting. When transcription finishes, the meeting appears under Transcripts with View, Copy, Open and Delete. Transcripts are Markdown files in the app's data folder, behind the History lock if you use one.
On macOS 14.4 and later the call's own audio is recorded next to your mic, so headphones work. On older macOS, or in a room, it records the mic only. Real names for remote speakers need Accessibility and a call in Google Meet, Slack Huddles, Teams or Zoom.
